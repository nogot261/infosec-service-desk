# План проверки версии 2.0.0

**Дата подготовки:** 23.11.2026. **Статус:** частичная проверка, выпуск для окончательной сдачи не подтвержден.

## Методы

1. **Модульное тестирование.** Создание заявок, проверка статусов и ролей, формирование выборок; временная SQLite на каждый тест.
2. **Интеграционное тестирование.** Flask-маршруты, HTML-формы, запись в БД, CSV/XLSX и JSON-обмен.
3. **Граничные проверки.** Некорректные поля, отсутствие CSRF, чужая заявка, 501 строка при ограничении отображения 500, импорт неверного файла.
4. **Сценарное и визуальное тестирование.** Проход заявитель -> специалист -> закрытие; проверка ПК, ноутбука, телефона в четырёх браузерах.

## Что подтверждено на 23.11.2026

- Схема SQLite: **11 таблиц**.
- Отдельная учебная база: **3 учётные записи, 501 заявка, 251 закрытая заявка**.
- Сквозной пример заявки № 1: назначение, два комментария, перевод в состояния «В работе», «Решена», «Закрыта».
- Выборки предметного слоя возвращают **501** запись без фильтра и **251** с фильтром `closed`.
- Проверен синтаксис исходных Python-файлов и шаблонов Jinja2.

## Фактически проведённая повторная проверка без Flask

23.11.2026 запущена команда `python tools/offline_check.py`. Результат: **10 предметных проверок пройдено**. Включены: структура БД, учётные записи, 501/251, история, контрольный CSV, доступ к чужой заявке, допустимые статусы, обратная связь и JSON-обмен. Полный протокол: `docs/verification_offline.txt`.

Также подготовлены 48 функций автоматизированных тестов. Их полный повторный прогон невозможен в текущей среде без установленного Flask. Запуск `python -m pytest -q` завершился на импорте `tests/conftest.py` ошибкой `ModuleNotFoundError: No module named 'flask'`; это ограничение среды, а не подтверждённый дефект приложения.

## Что не подтверждено

- Полный повторный прогон pytest на Flask: пакет Flask отсутствует в текущей рабочей среде, загрузка недоступна.
- HTTP-ответы CSV/XLSX и открытие страниц в работающем приложении.
- Проверка Edge, Яндекс Браузера, Firefox и Chrome на трёх реальных устройствах.
- Публичный хостинг, релизный тег, фактическая история коммитов автора.

Неподтверждённые результаты нельзя переносить в отчёт как успешные. После установки зависимостей запустите `python -m pytest -q` и запишите фактический результат.
