# Пояснения к программному коду

Здесь описаны значимые участки кода и причины выбранной реализации. Полные исходники
сохраняются в каталогах `src/infosec_desk` и `tests`.

## Запуск: `run.py`

- `ROOT = Path(__file__).resolve().parent` определяет корневую папку по положению самого файла, поэтому запуск не зависит от текущего системного каталога.
- `sys.path.insert(...)` обеспечивает импорт локального пакета из папки `src` без предварительной установки.
- `prepare_runtime()` проверяет доступность веб-зависимостей. Если они уже установлены, приложение не выполняет дополнительные действия.
- `venv.EnvBuilder(with_pip=True)` создает локальную среду только при необходимости. В ней не затрагиваются пользовательские глобальные пакеты Python.
- Переменная `interpreter` вычисляется с учетом различия системных каталогов `Scripts` и `bin`. Команда пользователя от этого не меняется.
- Повторный вызов с подготовленным интерпретатором запускает сервер с теми же аргументами.
- Настройка UTF-8 для консольных потоков Windows позволяет печатать русские сообщения также при перенаправлении вывода.
- `os.chdir(ROOT)` обеспечивает одинаковое расположение относительного пути к базе на обеих ОС.

## База: `db.py`

- `SCHEMA` содержит все определения пяти таблиц, ограничений внешних ключей и индексов. Независимая копия находится в `sql/schema.sql`.
- `PRAGMA foreign_keys = ON` включает контроль связности записей SQLite для текущего подключения.
- `users` хранит учетные записи. `password_hash` содержит только проверочное значение, а не пароль.
- `assets` хранит уникальные инвентарные объекты, связываемые с заявками.
- `tickets` содержит общие данные обращения. `author_id` обязателен, `assignee_id` и `asset_id` могут быть пустыми.
- `comments` хранит сообщения в карточках, `audit_events` сохраняет историю изменения состояния.
- `connect()` создает подключение и настраивает возврат строк по названиям полей.
- `initialize()` создает каталог хранения базы, после чего выполняет DDL-команды с `IF NOT EXISTS`.
- `transaction()` открывает запись командой `BEGIN IMMEDIATE`. При исключении вызывается `rollback()`, при успехе - `commit()`; подключение закрывается в блоке `finally`.

## Проверка данных: `security.py`

- `password_hash()` проверяет минимальную длину пароля, генерирует случайную соль и вычисляет PBKDF2-HMAC-SHA256 с заданным количеством итераций.
- Формат сохраненного значения включает идентификатор алгоритма, число итераций, соль и хеш. Он позволяет проверять пароль позднее без хранения исходной строки.
- `verify_password()` обрабатывает ошибочные записи безопасным отказом и сравнивает значения посредством `hmac.compare_digest()`.
- `clean_text()` удаляет внешние пробелы и проверяет диапазон допустимой длины.
- `new_csrf_token()` создает случайный токен формы, а `check_csrf()` сравнивает токен с сохраненным в сессии.

## Предметные операции: `service.py`

- `CATEGORIES`, `PRIORITIES`, `STATUSES` и `ROLES` фиксируют разрешенные коды. Текст интерфейса хранится отдельно от значений базы.
- `TRANSITIONS` задает допустимые последовательности обработки обращения.
- `create_user()` проверяет имя, роль и пароль, затем записывает нового пользователя. Проверка уникальности логина дополнительно осуществляется ограничением БД.
- `authenticate()` ищет активную запись пользователя и проверяет пароль. В случае ошибки возвращается `None`.
- `list_tickets()` применяет ограничения по роли и необязательные фильтры. Для заявителя поиск всегда ограничен его `author_id`.
- `get_ticket()` не возвращает чужую карточку заявителю; комментарии и история загружаются только для разрешенной заявки.
- `create_ticket()` проверяет все входные поля и существование указанного объекта защиты. Запись заявки и события создания выполняются в одной транзакции.
- `add_comment()` запрещает запись в недоступную заявку и добавляет событие в журнал.
- `update_ticket()` проверяет роль, существование заявки, допустимость перехода и квалификацию исполнителя. Даты изменения и закрытия обновляются автоматически.
- `statistics()` вычисляет сводные показатели для реестра пользователя. `audit_events()` возвращает ограниченное число последних записей истории.

## Обработка запросов: `web.py`

- `create_app()` создает приложение FastAPI, связывает шаблоны и базу и подключает механизм сессий.
- `current_user()` получает идентификатор из проверенной сессии, затем считывает действующую запись из базы.
- `require_user()` запрещает маршруты гостям и ролям без соответствующих прав. Для проверки чужих заявок дополнительно используется `get_ticket()`.
- `secure_form()` читает содержимое формы и проверяет CSRF до выполнения операций записи.
- GET-маршруты получают данные для HTML. POST-маршруты вызывают сервисные функции, а после сохранения перенаправляют браузер, чтобы обновление страницы не дублировало действие.
- При вводе неправильных данных пользователю возвращается сообщение об ошибке. Ошибка прав доступа не преобразуется в разрешенную операцию.
- `/export.csv` формирует таблицу в UTF-8 и нейтрализует строки, которые табличный редактор может принять за формулы.
- `/health` выполняет проверку доступа к базе, необходимую для тестирования запуска.

## Интерфейс: `templates/` и `static/`

- `base.html` определяет единый каркас навигации. Доступность отдельных пунктов меню зависит от роли.
- `login.html` содержит форму входа с CSRF-токеном.
- `dashboard.html` отображает сводку и последние заявки.
- `tickets.html` выводит фильтруемый список. `_table.html` используется как общий шаблон строк реестра.
- `ticket_new.html` содержит форму создания, `ticket_detail.html` - описание, комментарии, управление статусом и историю.
- `assets.html`, `users.html` и `audit.html` дают доступ к соответствующим справочникам и журналу.
- `style.css` отвечает за адаптивную раскладку, шрифты, таблицы, поля ввода и поведение на узких экранах.

## Проверки: `tests/`

- `conftest.py` готовит временную базу, тестовых пользователей и клиент запросов. Это исключает изменение реальных рабочих записей.
- `test_service.py` проверяет хеширование, права на карточки, смену состояний, валидацию полей, комментарии и журнал.
- `test_web.py` проверяет вход, выход, создание заявки через HTTP, CSRF, права администратора, экспорт и экранирование HTML.
- `test_cli.py` проверяет выполнение служебной команды, создание первого администратора и запрет небезопасного сетевого запуска.
