# Архитектура рабочей версии

Вход в приложение начинается с `run.py`, для размещения на Render используется `wsgi.py`. Flask принимает HTTP-запросы и проверяет сеанс пользователя. Сервисный модуль `service.py` выполняет операции с заявками, назначениями и историей. SQLite-модуль `db.py` отвечает за создание таблиц, транзакции и миграцию схемы. HTML-шаблоны не обращаются к базе напрямую.

Создание заявки: форма отправляет данные на сервер; обработчик проверяет CSRF и роль; сервис проверяет категорию и приоритет, записывает заявку и историю, возвращает её номер. Изменение статуса проходит тем же порядком.

Разграничение доступа осуществляется в обработчике и сервисе: скрытый пункт меню не заменяет проверку URL. Отдельное правило действует для файлов-вложений: доступ к файлу разрешён только тому, кому доступна его заявка.

В учебной базе содержатся 11 прикладных таблиц, схема находится в `sql/schema.sql`, изображение - в `docs/diagrams/database_11.svg`. Проверка структуры и реестра описана в `docs/test_plan.md`.
