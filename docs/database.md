# Структура базы данных

В проекте используется SQLite с проверкой внешних ключей и ограничениями целостности. Файл создается при первом запуске.

| Таблица | Назначение |
|---|---|
| `users` | Пользователи, роли и хеши паролей |
| `assets` | Средства защиты информации |
| `tickets` | Заявки и их состояние |
| `comments` | Переписка по обращениям |
| `audit_events` | История действий по заявкам |

Связи: заявитель (`tickets.author_id`) ссылается на `users`; назначенный исполнитель (`tickets.assignee_id`) также ссылается на `users`. Объект обслуживания (`tickets.asset_id`) ссылается на `assets`. Комментарии и события связаны с заявкой и инициатором действия.

Ограничения: обязательные поля `NOT NULL`, уникальные логины и инвентарные номера, фиксированные варианты роли, категории, приоритета и статуса (`CHECK`), внешние ключи, индексы по типовым операциям поиска. Запись изменений выполняется внутри транзакций.

Резервная копия при остановленном приложении может быть выполнена копированием файла `instance/infosec.sqlite3`. При работающем приложении используйте штатный механизм SQLite Backup API, а не простое копирование открытого файла.
