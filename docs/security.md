# Безопасность

## Роли

| Действие | Заявитель | Специалист | Администратор |
|---|---|---|---|
| Смотреть собственные заявки | Да | Да | Да |
| Смотреть все заявки | Нет | Да | Да |
| Создавать и комментировать доступные заявки | Да | Да | Да |
| Менять статус и исполнителя | Нет | Да | Да |
| Смотреть реестр средств защиты | Да | Да | Да |
| Добавлять средства защиты | Нет | Нет | Да |
| Управлять учетными записями | Нет | Нет | Да |
| Смотреть полный журнал действий | Нет | Нет | Да |
| Экспортировать реестр | Нет | Да | Да |

## Реализованные меры

- Пароли хранятся как PBKDF2-HMAC-SHA256 с уникальной солью и 310000 итерациями.
- Учетные записи и просмотр заявок проверяются в бизнес-логике и в маршрутах.
- Изменяющие запросы защищены CSRF-токенами с проверкой постоянного времени.
- Cookies подписаны, HTTP-only и SameSite=Lax; `Secure` включается при HTTPS.
- Шаблоны экранируют HTML; обращения к SQLite используют параметры.
- Валидация ограничивает длину полей и допустимые статусы.
- Сведения о действиях фиксируются в журнале для каждой заявки.
- База и файлы настроек исключены из публикации в Git.

## Эксплуатационные требования

Демонстрационные учетные записи пригодны только для запуска на локальном компьютере. Для эксплуатации следует создать отдельного администратора и обеспечить TLS, секрет сессии, ограниченный доступ к файлу БД, резервное копирование и защиту конечного устройства.

Наличие этих мер не является подтверждением соответствия отраслевым требованиям безопасности. Перед промышленным вводом необходимы проверка модели угроз, аудит конфигурации и приемочные испытания.
