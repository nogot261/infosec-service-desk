# Проверка системы

Проверки выполняются на отдельной базе, не содержащей пользовательских данных.

## Подготовка

```bash
python run.py seed-demo --db instance/demo.sqlite3
python run.py serve --db instance/demo.sqlite3
```

Откройте `http://127.0.0.1:8000`. Для проверки используйте учетные записи из
таблицы демонстрационного доступа в `README.md`.

## Контрольные сценарии

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Вход администратора | Доступны разделы, меню и панель заявок |
| 2 | Вход с неверным паролем | Показано сообщение об ошибке, вход не выполняется |
| 3 | Создание заявки заявителем | Создана карточка с номером, запись в SQLite |
| 4 | Открытие чужой заявки заявителем | Просмотр отклонен |
| 5 | Назначение специалиста | Исполнитель сохранен |
| 6 | Переход Новая -> В работе -> Решена -> Закрыта | Все разрешенные переходы сохраняются |
| 7 | Переход Новая -> Закрыта | Операция отклонена |
| 8 | Комментарий | Текст и автор видны в карточке |
| 9 | Добавление средства защиты администратором | Запись появляется в справочнике |
| 10 | Доступ заявителя к разделу Пользователи | Ответ 403 |
| 11 | Экспорт списка специалистом | CSV содержит доступные заявки |
| 12 | Отправка формы без CSRF-токена | Ответ 403 |
| 13 | Ввод HTML в название | Теги показываются как текст |
| 14 | Выход | Сеанс завершается |
| 15 | Повторный запуск приложения | Записи сохраняются, повторная установка не нужна |
| 16 | Смена пароля локальной командой | Старый пароль отклоняется, новый принимается |

## Автоматизированная проверка

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src tests run.py
```

GitHub Actions повторяет проверки на Windows и Ubuntu с несколькими версиями Python.
При приемке необходимо дополнительно проверить загрузку реального браузера,
работу на целевой ОС и резервное копирование SQLite.
