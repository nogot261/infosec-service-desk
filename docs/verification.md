# Проверка информационной системы

## 1. Запуск

На Windows и Ubuntu выполняется одна команда из корня репозитория:

```bash
python run.py
```

При первом запуске создается база `instance/infosec.sqlite3`. Приложение сообщает адрес
`http://127.0.0.1:8000` и первоначальный пароль администратора. Пароль необходимо сохранить.
После повторного запуска уже существующие учетные записи и заявки сохраняются.

## 2. Проверка ролей

Войти администратором. Создать заявителя и специалиста через раздел «Пользователи».
В разделе «Средства защиты» зарегистрировать объект с уникальным инвентарным номером.
Войти под заявителем и создать обращение. Проверить, что:

1. Заявка присутствует в реестре, имеет номер `З-000001` (для пустой базы) и статус «Новая».
2. Заявитель видит созданное обращение и может оставить комментарий.
3. Заявитель не может открыть `/users`, `/audit` и `/export.csv`.
4. Заявитель не видит заявки других сотрудников.

Войти под специалистом и открыть заявку:

1. Назначить себя исполнителем, изменить статус на «В работе».
2. Сохранить комментарий с результатом диагностики.
3. Изменить статус на «Решена», затем на «Закрыта».
4. Убедиться, что история отображает выполненные действия.
5. Получить CSV через пункт экспорта и открыть файл в табличном редакторе.

## 3. Негативные сценарии

- Неверный пароль не должен приводить ко входу.
- Пользователь-заявитель не должен менять статусы.
- Нельзя сразу перевести новую заявку в состояние «Закрыта».
- Нельзя назначить исполнителем учетную запись заявителя.
- Отправка формы без действительного CSRF-токена возвращает HTTP 403.
- Некорректные категория и приоритет, слишком короткие тема и описание отклоняются.
- Текст с HTML-тегами отображается как текст, не исполняется в браузере.

## 4. Автоматические тесты

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src tests run.py
```

Конвейер `.github/workflows/tests.yml` запускает проверки на Windows и Ubuntu с версиями
Python 3.10, 3.12 и 3.13. В репозитории находится только схема базы, исходный код и тесты.
Файл базы с личными сведениями и паролями не публикуется.

## 5. Проверка SQL отдельно

В `sql/schema.sql` хранится DDL-схема, применяемая системой при создании базы. Ее можно
выполнить в SQLite командой `sqlite3 test.sqlite3 < sql/schema.sql` при наличии консольной
утилиты SQLite. Для обычной работы отдельная установка SQLite не требуется.
