# InfoSec Desk - преддипломная практика

Приложение для регистрации и обработки заявок на обслуживание средств защиты информации. Язык Python, веб-фреймворк Flask, база SQLite. Версия исходного кода **2.0.0** (23 ноября 2026 года).

**Статус:** доработанная учебная версия. База данных и предметные функции проверены локально. Полный запуск Flask, браузерная проверка и публикация требуют отдельного подтверждения. Не используйте демонстрационные пароли на реальном сервере.

## Что умеет приложение

- Создавать заявки, назначать специалистов, менять статусы, вести комментарии и историю изменений.
- Разделять права заявителя, специалиста и администратора.
- Показывать 12 справочных страниц без входа и сохранять обратную связь.
- Вести справочник СЗИ, каталог услуг, вложения, уведомления и настройки службы.
- Выгружать весь реестр либо результат фильтрации в CSV и XLSX.
- Импортировать и экспортировать JSON справочника СЗИ (также есть интерфейс администратора).

## Запуск с нуля

Требуется Python 3.10+ и доступ к установке зависимостей из PyPI. Распакуйте проект, откройте терминал в каталоге `infosec-service-desk`.

Windows:

```powershell
python run.py seed-demo --db instance/demo.sqlite3
python run.py serve --db instance/demo.sqlite3
```

Ubuntu:

```bash
python3 run.py seed-demo --db instance/demo.sqlite3
python3 run.py serve --db instance/demo.sqlite3
```

При первом запуске `run.py` подготовит окружение и установит версии из `requirements.txt`. Для обычного запуска без учебной БД используйте `python run.py` (Windows) или `python3 run.py` (Linux). Сервер откроется на `http://127.0.0.1:8000`.

**Важно:** файл `instance/demo.sqlite3` уже вложен в комплект. Повторно запускать `seed-demo` необязательно: программа увидит существующую базу и не добавит дубликаты.

## Учебные учетные записи

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `DemoPass123!` |
| Специалист | `operator` | `DemoPass123!` |
| Заявитель | `employee` | `DemoPass123!` |

Это вымышленные учётные записи. На Render указанные пароли автоматически заменяются секретным значением `INFOSEC_DEMO_PASSWORD`. Публикуйте только учебные данные, не реальные заявки.

## Проверка

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
```

Для проверки операций без запуска сайта выполните `python tools/offline_check.py` (10 проверок в подготовленной учебной БД). Полноценные веб-тесты запускаются после установки Flask. Дополнительные тесты предусмотрены в `tests/test_requirements.py`. В учебной БД **501 заявка, 251 закрытая**. Поиск и отображение ограничивают только страницу реестра; экспорт не ограничен 500 строками. Перечень проверок и сведения о том, что проверено, а что ещё требует прогона: `docs/test_plan.md`.

## Проверка версии и ограничения

Интернет-публикация, запуск в Chrome, Firefox, Яндекс Браузере и Edge, а также история 50 содержательных коммитов автора **не подтверждены данным архивом**. Версию 2.0.0 нельзя считать окончательно принятой до полного прогона. В `docs/release.md` есть список оставшихся проверок.

Для боевого развёртывания нужны HTTPS, постоянный секрет сеанса, безопасное хранение резервных копий и учёт требований к персональным данным. Нельзя использовать демонстрационную базу или пароли в публичном режиме.

## Публикация на Render

В корне проекта есть `render.yaml`, `wsgi.py` и `requirements-deploy.txt`.
Для Render достаточно Python Web Service: Docker необязателен. Пошаговая
инструкция и сведения о сбросе учебной базы находятся в `docs/deployment_render.md`.
Для внешнего сервера в `render.yaml` создаются отдельный секрет сеансов и
секретный пароль демонстрационных пользователей.
