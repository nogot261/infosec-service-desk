# InfoSec Service Desk

Веб-система регистрации и обработки заявок на обслуживание систем защиты информации.

## Возможности

- Регистрация и поиск заявок, приоритеты и категории
- Назначение исполнителей и контроль жизненного цикла заявки
- Комментарии и история действий
- Учет средств защиты информации
- Роли: заявитель, специалист, администратор
- Экспорт реестра заявок в CSV
- Хранение данных в SQLite без отдельного сервера БД

## Требования

Python 3.10 или новее. Windows 10/11 или Ubuntu 22.04/24.04 (и другие системы с Python 3.10+).

## Единый запуск на Windows и Ubuntu

Установите Python 3.10 или новее, откройте терминал в папке проекта и выполните:

```bash
python run.py
```

При первом запуске программа установит зависимости в `.venv` (если их нет), создаст
базу данных `instance/infosec.sqlite3` и первоначального администратора.
**Логин: `admin`. Пароль: случайный, выводится в терминале только один раз.**
Сохраните этот пароль. Пароль `DemoPass123!` для обычного запуска не подходит.

Откройте `http://127.0.0.1:8000` и войдите с логином `admin` и паролем,
который был показан в терминале. Для последующих запусков используется та же
команда `python run.py`. Существующие пользователи и заявки сохраняются.

### Если пароль администратора не сохранился

Остановите сервер сочетанием `Ctrl+C` и выполните:

```bash
python run.py reset-password
```

Введите новый пароль (не менее 10 символов) два раза. При вводе пароль
не отображается. Команда меняет пароль существующего `admin` без создания
нового пользователя, удаления базы или заявок. Затем запустите
`python run.py` и войдите как `admin` с новым паролем.

Если нужно изменить пароль другого администратора:

```bash
python run.py reset-password --username admin2
```

Команда требует локального доступа к проекту и файлу БД. Не предоставляйте
посторонним доступ к файлам системы.

### Демонстрационные пользователи и данные

Тестовые пользователи `admin`, `operator`, `employee` **не создаются**
при обычном запуске. Чтобы создать их и несколько примеров заявок,
используйте отдельную демонстрационную базу:

```bash
python run.py seed-demo --db instance/demo.sqlite3
python run.py serve --db instance/demo.sqlite3
```

После запуска перейдите на `http://127.0.0.1:8000` и войдите под одним из
демонстрационных пользователей:

| Логин | Пароль | Роль |
|---|---|---|
| admin | DemoPass123! | Администратор |
| operator | DemoPass123! | Специалист |
| employee | DemoPass123! | Заявитель |

**Важно:** `seed-demo` добавляет пользователей только в базу, в которой их
еще нет. Для уже запущенной обычной базы команда ничего не добавит.
Не используйте демонстрационные пароли в системе, доступной по сети.
После ознакомления вернитесь к основной базе командой `python run.py`.

### Требования к окружению

Нужен Python 3.10+ с модулем `venv` и командой `python` в PATH.
Если в Ubuntu доступна только команда `python3`, можно установить
пакет `python-is-python3`. Для первой установки зависимостей требуется
интернет. Последующие запуски работают без сети.

Установщик поддерживает SOCKS-прокси. При ошибке соединения проверьте
`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `PIP_PROXY` и доступность
локального прокси.

## Команды обслуживания

| Команда | Назначение |
|---|---|
| `python run.py` | Создать учетную запись при первом старте и запустить сервер |
| `python run.py init-db` | Создать пустую базу |
| `python run.py create-admin` | Добавить нового администратора вручную |
| `python run.py reset-password` | Сменить пароль существующего `admin` |
| `python run.py seed-demo` | Добавить тестовые записи в пустую базу |

В файле `.env.example` приведены переменные окружения для настройки секретов,
порта и хранения базы. Для сетевой эксплуатации нужны HTTPS, резервное
копирование и постоянный `INFOSEC_SECRET_KEY`.

## Границы реализации

Приложение представляет локальный прототип с реальным сохранением заявок. Не предусматривает подключения к сетевому оборудованию, Active Directory, антивирусным консолям и другим внешним системам. Установка на сервер, резервное копирование, TLS, мониторинг и дополнительные меры защиты должны выполняться администратором организации до ввода в эксплуатацию.
